# 依赖选型

调研日期：2026-10-20。核对 npm registry 的版本、engines、许可证和依赖，以及仓库文档和公开 Issue。以下 Star 仅作社区使用信号，不作兼容性保证，也不据此宣称没有安全问题。

| 用途      | 结论                                                                                                                                                     | 理由与限制                                                                                                                                                                                                                                                                                                                                                                  |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 系统壁纸  | [`wallpaper` 7.3.1](https://github.com/sindresorhus/wallpaper)                                                                                           | MIT、ESM、附带类型、无运行时依赖；仓库约 1.1k Star，复用自带原生二进制，无需编译器/Python。Windows 多屏和重复设置存在公开 Issue，因此查询当前路径后跳过重复设置，文档不承诺逐屏及所有 Space 支持。                                                                                                                                                                          |
| Bing 封装 | 不引入 [`wonderful-bing-wallpaper`](https://github.com/surmon-china/wonderful-bing-wallpaper) / [`@oxoyo/xbw`](https://www.npmjs.com/package/@oxoyo/xbw) | npm 页面显示分别约六年/四年未发布；其薄封装仍需补齐超时、重试、校验和缓存。使用内置 fetch，把非稳定 Bing 接口隔离在 bing.ts；不使用第三方壁纸代理服务。                                                                                                                                                                                                                     |
| CLI       | [`commander` 15](https://github.com/tj/commander.js)                                                                                                     | MIT、无运行时依赖、附带类型、成熟的子命令及错误处理；核对 engines 后采用 Node >=22.12。[`cac` 7](https://github.com/cacjs/cac) 同样轻量可用，但本工具嵌套子命令及帮助更适合 Commander。                                                                                                                                                                                     |
| 用户目录  | [`env-paths` 4](https://github.com/sindresorhus/env-paths)                                                                                               | MIT、附带类型，按 OS 返回 config/data/cache/log 目录，运行时仅一个文件名校验依赖。无需引入完整配置框架。                                                                                                                                                                                                                                                                    |
| 图片校验  | [`image-size` 2](https://github.com/image-size/image-size)                                                                                               | MIT、附带类型、无运行时依赖；读取 JPEG 头和尺寸，另外检查 JPEG 起止标记和 SHA-256。无需 sharp/ImageMagick。不是完整像素解码器，不保证发现所有损坏。                                                                                                                                                                                                                         |
| 定时任务  | 系统命令适配                                                                                                                                             | [`node-schedule`](https://github.com/node-schedule/node-schedule) 虽约 9.2k Star，但明确为进程内调度；[`node-windows`](https://github.com/coreybutler/node-windows) 侧重服务和提权，超出需求；npm `launchd` 仅 0.1.0，registry 修改时间为 2023 年，且只覆盖 macOS；查询 `windows-task-scheduler` 返回 404。未找到适合本工具、能同时覆盖两个用户级调度器的成熟轻量统一封装。 |
| 工程      | TypeScript tsc + Vitest 5 + Prettier                                                                                                                     | 保留 ESM 模块和外部原生依赖，tsc 已能直接输出 JS 和声明文件，无需增加打包层。Vitest Mock 网络与系统调用。Prettier 使用仓库风格。                                                                                                                                                                                                                                            |

Windows 通过 PowerShell 调用系统 Task Scheduler COM API；macOS 通过 launchctl 和 LaunchAgent plist。只实现任务管理胶水，不自行实现 Win32 壁纸接口或 AppleScript。execFile 禁用 shell，Windows 脚本仅插入 Base64 JSON 数据。

系统行为参考：[Microsoft LogonType](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-logontype-simpletype)、[Apple 用户 LaunchAgent](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)。Bing 图片由 Bing 直接提供，端点不是稳定公开 API。
